
🔹 Callback

A callback is a function passed as an argument to another function and is executed after the completion of an operation (usually asynchronous).

👉 When multiple callbacks are nested, it becomes hard to read and manage.


---

🔹 Callback Hell

Callback hell happens when:

Multiple callbacks are nested inside each other

Code becomes:

Difficult to read

Hard to debug

Difficult to maintain



📌 This is also called “Pyramid of Doom”


---

🔹 Does callback cause delay?

❌ Callback itself does NOT cause delay

✔ Delay is caused by:

Asynchronous operations (API calls, timers, file reading)


Callbacks are just a way to handle async results.


---

🔹 Synchronous (Sync)

Synchronous code executes line by line, one after another.

👉 Each operation waits for the previous one to complete.

console.log("1");
console.log("2");
console.log("3");

✅ Output (always):

1
2
3


---

🔹 Asynchronous (Async)

Asynchronous code does not block execution.

👉 Time-taking operations are sent aside, and remaining code runs first.

console.log("1");

setTimeout(() => {
  console.log("2");
}, 1000);

console.log("3");

✅ Output:

1
3
2

📌 Not random, but event-loop based


---

🔹 Callback Hell Solution

✔ Promises were introduced to avoid callback hell

Promises:

Improve readability

Handle errors properly

Avoid deep nesting


fetchData()
  .then(result => process(result))
  .then(final => display(final))
  .catch(error => console.log(error));


---

🔹 Async/Await (Best Practice)

Async/await is built on top of Promises and gives clean, synchronous-looking code.

async function getData() {
  try {
    const data = await fetchData();
    console.log(data);
  } catch (err) {
    console.log(err);
  }
}


---

🧠 What to Say in Interview (Short & Strong)

> “Callbacks handle async operations, but multiple nested callbacks cause callback hell.
Promises and async/await were introduced to solve this problem and improve readability and error handling.”
