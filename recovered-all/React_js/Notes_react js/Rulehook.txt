

Rules of Hooks .

Think of hooks like numbered boxes inside React.
React remembers data by the order in which hooks are written.

If the order changes → React gets confused ❌

That’s why rules exist.


---

Rule 1: Always call hooks at the TOP

What this means

👉 Write hooks at the start of the component
👉 Do not put hooks inside:

if

for

while

functions

buttons / events



---

❌ Wrong

if (login) {
  useState(0);   // ❌
}

✅ Right

const [count, setCount] = useState(0);

if (login) {
  // use count here
}

📌 Logic goes inside, hook stays on top.


---

Rule 2: Use hooks ONLY in React components

Allowed places ✅

React function component

Custom hook (your own hook)



---

❌ Wrong

function normalFunction() {
  useEffect(() => {}); // ❌
}

✅ Right

function MyComponent() {
  useEffect(() => {
    console.log("Hello");
  }, []);
}


---

Custom Hook Rule (Easy)

If you make your own hook:

Name must start with use


✅ Right

function useToggle() {
  const [value, setValue] = useState(false);
  return [value, setValue];
}

❌ Wrong

function toggle() {} // ❌


---

Simple Reason (Most Important)

React counts hooks in order.

Example:

useState()  // 1st
useEffect() // 2nd

If you put a hook in if, order changes sometimes → bug 💥

So: ✔ Same order every time
✔ Hooks on top


---

Golden Rule (Remember This 🔑)

> Hooks go on top, not inside conditions or loops.




---

One-Line Interview Answer 🎯

> Hooks must be used only at the top level of React function components so React can track state correctly.
