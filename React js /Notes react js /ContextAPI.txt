
---

🔹 Basic Level (Warm-up)

1. What is Context API?

Answer:
Context API is a React feature used to share data across components without passing props at every level (avoids props drilling).


---

2. Why do we need Context API?

Answer:
To avoid props drilling and manage global data like authentication, themes, and user info.


---

3. What problem does Context API solve?

Answer:
It solves the problem of passing data through deeply nested components unnecessarily.


---

4. When should you NOT use Context API?

Answer:
When data is needed only by a few components or changes very frequently, as it can cause unnecessary re-renders.


---

🔹 Intermediate Level (Most asked)

5. What are the main components of Context API?

Answer:

createContext()

Provider

Consumer / useContext()



---

6. Difference between Props and Context?

Answer:

Props	Context

Passed component to component	Available globally
Leads to props drilling	Avoids props drilling
Best for local data	Best for global data



---

7. How does useContext() work?

Answer:
useContext() allows a component to consume context values directly without using a Consumer component.


---

8. What happens when Context value changes?

Answer:
All components consuming that context will re-render.


---

9. Can we use multiple Contexts in one component?

Answer:
Yes, a component can consume multiple contexts using multiple useContext() calls.


---

🔹 Advanced Level (Tricky / Senior)

10. Context API vs Redux?

Answer:

Context API	Redux

Built-in React feature	External library
Good for small/global state	Best for large/complex state
Simple setup	Boilerplate but powerful
Causes re-renders easily	Better performance control



---

11. How do you optimize Context API performance?

Answer:

Split contexts (don’t store everything in one)

Memoize values using useMemo

Avoid frequent updates in context



---

12. What is props drilling? Explain with example.

Answer:
Passing props through intermediate components that don’t need the data, just to reach a deeply nested component.


---

13. Can Context API replace Redux?

Answer:
No. Context API is not a full state management solution. Redux is better for complex state logic, middleware, and debugging.


---

14. What is the default value in createContext()?

Answer:
The default value is used only when a component is not wrapped inside a Provider.


---

🔹 Scenario-Based Questions (Very Important)

15. When would you choose Context API over Redux?

Answer:
When the app is small or medium and needs simple global data like theme, auth, or language.


---

16. What issues can occur if Context is overused?

Answer:

Performance problems

Unnecessary re-renders

Harder debugging



---

17. How do you share state between unrelated components?

Answer:
Using Context API or a state management library like Redux.
