
📘 Updating Object in State – React JS

(Parent–Child Relationship Concept)


---

🔹 What is “Updating Object in State”?

When your state is an object, you must update it without changing the original object.

React does not allow direct modification like:

data.name = "Anil Sahu"; ❌ Wrong

You must always create a new object copy.


---

🔹 Why we need special method?

Because React checks reference change, not value change.

If you modify the same object, React will not re-render.


---

🔹 Initial State Example

const [data, setData] = useState({
  name: "Anil",
  address: {
    city: "Delhi",
    country: "India"
  }
});


---

🔹 Wrong Way

const handleName = () => {
  data.name = "Anil Sahu";   // ❌ direct mutation
  setData(data);
};

UI will NOT update properly.


---

🔹 Correct Way (Spread Operator)

const handleName = () => {
  setData({
    ...data,
    name: "Anil Sahu"
  });
};


---

🔹 Updating Nested Object

const handleCity = () => {
  setData({
    ...data,
    address: {
      ...data.address,
      city: "Mumbai"
    }
  });
};


---

🔹 JSX

<h2>Name: {data.name}</h2>
<h2>City: {data.address.city}</h2>
<h2>Country: {data.address.country}</h2>

<button onClick={handleName}>Update Name</button>
<button onClick={handleCity}>Update City</button>


---

🔹 How it Works

Step	Explanation

...data	copies all old data
name: "Anil Sahu"	updates only name
...data.address	copies nested object
city: "Mumbai"	updates city only



---

🔹 Purpose

Benefit	Reason

No bugs	No direct mutation
UI updates correctly	New object reference
Clean code	Predictable behavior
